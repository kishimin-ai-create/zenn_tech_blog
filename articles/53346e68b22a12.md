## なぜ調べたか

WebアプリケーションのE2Eテストを行うため、Playwrightの基本的な使い方を調べました。

今回は、テストの実行方法やテストコードの書き方から、コード生成、スクリーンショット、動画撮影、ビジュアルリグレッションテスト、Page Object Modelまでをまとめます。

## 学んだこと

### E2Eテストとは

> E2EテストはEnd-to-End Testingの略で、一般的にシステムの一連の動作を最終チェックするテストのことです。

出典：

https://gihyo.jp/book/2024/978-4-297-14220-9

### Playwrightとは

Playwright公式ドキュメントでは、次のように説明されています。

> Playwright Test is an end-to-end test framework for modern web apps. It bundles test runner, assertions, isolation, parallelization and rich tooling. Playwright supports Chromium, WebKit and Firefox on Windows, Linux and macOS, locally or in CI, headless or headed, with native mobile emulation for Chrome (Android) and Mobile Safari.

**日本語訳**

Playwright Testは、最新のWebアプリ向けのエンドツーエンドテストフレームワークです。テストランナー、アサーション、隔離機能、並列処理、そして充実したツール群を統合しています。

Playwrightは、Windows、Linux、macOS上のChromium、WebKit、Firefoxに対応しており、ローカル環境やCI環境、ヘッドレスモードやヘッド付きモードでの実行が可能です。また、Chrome（Android）およびMobile Safari向けのネイティブモバイルエミュレーションもサポートしています。

出典：

https://playwright.dev/docs/intro#introduction

### テスト前の準備

Playwrightを導入します。

```bash
npm init playwright@latest
```

初期設定を行い、必要なブラウザをインストールします。

参考：

https://playwright.dev/docs/intro

### テストの実行

CLIを使ってテストを実行します。

```bash
npx playwright test
```

UIモードを使用すると、テストの実行状況を確認しながらテストできます。

```bash
npx playwright test --ui
```

参考：

https://playwright.dev/docs/running-tests

### テストの書き方

基本的には、以下の流れでテストを書きます。

1. テストしたいページにアクセスする
2. 要素を取得する
3. 必要に応じて操作する
4. 期待どおりの結果になっているか確認する

例えば、ログイン画面の表示を確認する場合は以下のようになります。

```ts
import { test, expect } from "@playwright/test";

test("ログイン画面が表示される", async ({ page }) => {
  await page.goto("https://example.com/login");

  await expect(page.getByRole("button", { name: "ログイン" })).toBeVisible();
});
```

`page.goto()` でページにアクセスし、`getByRole()` で対象の要素を取得します。

`expect()` を使用すると、取得した要素が期待どおりの状態になっているかを検証できます。

PlaywrightのWeb向けアサーションは、指定した条件を満たすまで自動的に再試行します。タイムアウトまでに条件を満たさなかった場合、テストは失敗します。

参考：

https://playwright.dev/docs/test-assertions#auto-retrying-assertions

### テスト生成

Playwrightには、ブラウザ操作を記録してテストコードを生成する機能があります。

CLIからコード生成ツールを起動します。

```bash
npx playwright codegen https://example.com
```

`https://example.com` は、テスト対象のWebアプリケーションのURLに置き換えます。

ブラウザ上で操作すると、その操作に対応するコードが生成されます。

VS Code拡張機能の「Playwright Test for VSCode」でもコードを生成できます。

#### Record new

新しいテストファイルを作成し、ブラウザ操作を記録します。

#### Record at cursor

既存のテストファイルで、現在のカーソル位置からコードを生成します。

既存のテストに操作を追加したい場合に利用できます。

コード生成では、クリックや入力操作だけでなく、要素の表示やテキストなどを確認するアサーションも生成できます。

参考：

https://playwright.dev/docs/codegen

### フォーム操作のテスト

フォーム操作では、入力欄に値を入力したり、ボタンをクリックしたりできます。

例えば、ログインフォームを操作する場合は以下のようになります。

```ts
import { test, expect } from "@playwright/test";

test("ログインすると一覧画面に遷移する", async ({ page }) => {
  await page.goto("https://example.com/login");

  await page.getByRole("textbox", { name: "ユーザー名" }).fill("testuser");

  await page.getByLabel("パスワード").fill("password");

  await page.getByRole("button", { name: "ログイン" }).click();

  await expect(page).toHaveURL("https://example.com/lines");

  await expect(page.getByRole("list")).toBeVisible();
});
```

`fill()` でフォームに値を入力し、`click()` でボタンをクリックします。

ログイン後は、URLや一覧画面の表示を確認します。

※ URL、入力欄のラベル、認証情報はサンプルです。`example.com` にログイン画面が用意されているわけではないため、実際のアプリケーションに合わせて変更する必要があります。

参考：

https://playwright.dev/docs/input

### スクリーンショット

Playwrightでは、テスト中にスクリーンショットを撮影できます。

```ts
await page.screenshot({
  path: "screenshot/login.png",
});
```

ページ全体を撮影する場合は、`fullPage` を指定します。

```ts
await page.screenshot({
  path: "screenshot/login_full_page.png",
  fullPage: true,
});
```

特定の要素だけを撮影することもできます。

```ts
await page.getByRole("banner").screenshot({
  path: "screenshot/banner.png",
});
```

`path` に指定した画像の保存先は、プロジェクトのルートディレクトリを基準とした相対パスです。保存先のディレクトリも必要に応じて作成されます。

参考：

https://playwright.dev/docs/screenshots

### 動画撮影

Playwrightでは、テスト実行中のブラウザ操作を動画として記録できます。

動画撮影は、`playwright.config.ts` の `use` で設定できます。

例えば、Chromiumのテストで動画を撮影する場合は、次のように設定します。

```ts
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  projects: [
    {
      name: "chromium",
      use: {
        ...devices["Desktop Chrome"],
        video: "on",
      },
    },
  ],
});
```

`video: "on"` を指定すると、テスト実行時に動画を撮影します。

特定のテストファイルだけで動画撮影を有効にする場合は、`test.use()` を使用します。

```ts
import { test, expect } from "@playwright/test";

test.use({
  video: "on",
});

test("ログイン画面が表示される", async ({ page }) => {
  await page.goto("https://example.com/login");

  await expect(page.getByRole("button", { name: "ログイン" })).toBeVisible();
});
```

`test.use()` は、テストファイルのトップレベルや `test.describe()` 内で指定できます。

また、`launchOptions` の `slowMo` を指定すると、ブラウザ操作の実行速度を遅くできます。

```ts
{
  name: "chromium-video",
  use: {
    ...devices["Desktop Chrome"],
    video: "on",
    launchOptions: {
      slowMo: 500,
    },
  },
}
```

この設定では、ブラウザ操作の間に500ミリ秒の遅延を加えます。動画を確認する際に、操作の流れを追いやすくなります。

動画撮影を特定のテストに限定したい場合は、`testMatch` や `testIgnore` を使って、通常のテストと動画撮影用のテストを分けることもできます。

参考：

https://playwright.dev/docs/videos
https://playwright.dev/docs/test-use-options

### ビジュアルリグレッションテスト（VRT）

Playwrightでは、`toHaveScreenshot()` を使用して、保存済みの基準画像と現在の画面を比較するビジュアルリグレッションテスト（VRT）を実行できます。

例えば、ログイン画面を比較する場合は以下のようになります。

```ts
import { test, expect } from "@playwright/test";

test("ログイン画面のVRT", async ({ page }) => {
  await page.goto("https://example.com/login");

  await expect(page).toHaveScreenshot("login.png");
});
```

初回実行時には、比較対象となる基準画像がまだ存在しないため、画像を作成する必要があります。

基準画像の作成や更新には、以下のコマンドを使用します。

```bash
npx playwright test --update-snapshots
```

基準画像は、デフォルトではテストファイルと同じディレクトリ内に作成されるスナップショット用のディレクトリに保存されます。

基準画像が作成された後は、通常のテスト実行で現在の画面と比較できます。

```bash
npx playwright test
```

画面の仕様変更などによって表示が意図的に変わった場合は、差分を確認したうえで基準画像を更新します。

参考：

https://playwright.dev/docs/test-snapshots
https://playwright.dev/docs/screenshots

### Page Object Model

Page Object Model（POM）は、ページごとの要素や操作をまとめる設計パターンです。

複数のテストで同じ操作を繰り返す場合、操作を共通化することで、テストコードの重複を減らせます。

例えば、クラスを使ってログイン画面の操作を `LoginPage` にまとめます。

```ts
import type { Page, Locator } from "@playwright/test";

export class LoginPage {
  readonly page: Page;
  readonly userNameInput: Locator;
  readonly passwordInput: Locator;
  readonly loginButton: Locator;

  constructor(page: Page) {
    this.page = page;

    this.userNameInput = page.getByRole("textbox", {
      name: "ユーザー名",
    });

    this.passwordInput = page.getByLabel("パスワード");

    this.loginButton = page.getByRole("button", {
      name: "ログイン",
    });
  }

  async goto() {
    await this.page.goto("https://example.com/login");
  }

  async login(userName: string, password: string) {
    await this.userNameInput.fill(userName);
    await this.passwordInput.fill(password);
    await this.loginButton.click();
  }
}
```

テストコードからは、以下のように呼び出せます。

```ts
import { test, expect } from "@playwright/test";
import { LoginPage } from "../pages/login-page";

test("ログインすると一覧画面に遷移する", async ({ page }) => {
  const loginPage = new LoginPage(page);

  await loginPage.goto();
  await loginPage.login("testuser", "password");

  await expect(page).toHaveURL("https://example.com/lines");
});
```

ページ内の要素や操作方法が変更された場合、`LoginPage` を修正することで、複数のテストへの影響を抑えられます。

複数のページで共通する操作がある場合は、共通の基底クラスを作成したり、ヘッダーなどの共通コンポーネントを別のクラスに切り出したりする方法もあります。

クラスを使ったPOMの参考：

https://playwright.dev/docs/pom
https://dev.classmethod.jp/articles/playwright-page-object-model-with-percy/

また、TypeScriptでは、クラスではなく関数を使ってPage Object Modelを実装する方法もあります。

関数ベースのPOMの参考：

https://zenn.dev/sonicmoov/articles/ec18ed5659907c

### test.step

`test.step()` を使用すると、テスト内の処理を意味のある単位でまとめられます。

例えば、ログイン、画面遷移、スクリーンショットの撮影をそれぞれのステップに分割できます。

```ts
import { test, expect } from "@playwright/test";
import { LoginPage } from "../pages/login-page";

test("ログインすると一覧画面に遷移する", async ({ page }) => {
  const loginPage = new LoginPage(page);

  await test.step("ログイン", async () => {
    await loginPage.goto();
    await loginPage.login("testuser", "password");
  });

  await test.step("一覧画面への遷移", async () => {
    await expect(page).toHaveURL("https://example.com/lines");

    await expect(page.getByRole("list")).toBeVisible();
  });

  await test.step("スクリーンショット", async () => {
    await page.screenshot({
      path: "screenshot/lines.png",
      fullPage: true,
    });
  });

  await test.step("VRT", async () => {
    await expect(page).toHaveScreenshot();
  });
});
```

テストレポートでもステップごとに処理を確認できるため、どの操作で失敗したのかを把握しやすくなります。

参考：

https://playwright.dev/docs/api/class-test#test-step

## 一言でまとめると

Playwrightを使用すると、ブラウザ操作を自動化し、ユーザーの視点からWebアプリケーションの動作を確認できます。

コード生成機能でテスト作成を始めやすく、スクリーンショットや動画撮影を使って実行中の画面を記録できます。また、VRTによる画面の比較も可能です。

Page Object Modelや `test.step()` を使うことで、テストコードの整理や実行結果の確認もしやすくなります。
